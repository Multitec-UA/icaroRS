# manifest-enrichment — the converted manifest names the motor and the OpenRocket simulation it came from

Objective: `parameters.json` (written by `packages/rocketserializer`, passed through by the API, read by the web) carries the motor identity (designation, manufacturer, type, total impulse, burn time), the OpenRocket simulation its stored results come from (name, status, configuration) and the file's OpenRocket version, all from ONE coherent simulation, so the rocket card and the OpenRocket comparison row stop being opaque or possibly stale.
Branch: continues the `feat/workbench-rocket-exports` chain after slice 20 (tracker PR #113): slices 21 (serializer) and 22 (web). Runners: serializer `cd packages/rocketserializer && uv run python -m pytest -q`; icaro `cd packages/icaro && uv run python -m pytest -q`; API `cd apps/api && uv run python -m pytest -m "not integration" -q`; web `cd apps/web && npm test` + `npx tsc --noEmit` + `npm run lint` + `npm run i18n:check` + `npm run build` + `npm run e2e:visual:native` (re-baseline from CI's Linux artifact).
Decision judge: Opus 5.5 context-free (same recipe as workbench-product-polish); verdict in `## Log`.
Forecast: ~700 authored changed lines (serializer ~350 with tests and regenerated examples, web ~350 with tests and fixtures).

## Specs

- S1 One reference simulation. `ork_extractor` selects the **reference simulation** once, considering only simulations that have flight data (`<flightdata>` with at least one `<datapoint>`), in this order: (1) `uptodate` whose `<conditions><configid>` equals the `<motorconfiguration default="true">` id → selection `uptodate_default`; (2) first `uptodate` → `uptodate_other`; (3) `loaded` matching the default configuration, then first `loaded` → `loaded_default` / `loaded_other` (OpenRocket marks saved simulations as loaded; they are not stale by themselves); (4) first remaining simulation of any status → `fallback`; none → `null` (no stored results, no series, as today when the file has no simulation). That simulation feeds `stored_results` AND the time series (`datapoints`, `time_vector`, `burnout_position`) used for masses and positions. Today the summary comes from the first `<simulation>` and the series from the last one with data (`ork_extractor.py:136-169`, `stored_results.py:27`); this is a correctness fix, not a compatibility promise. `stored_results.selection` records the rule that fired. Acceptance examples under `examples/**/parameters.json` are regenerated and every value change is listed in the Log with its cause; a **value-level** regression test (with tolerance) pins MT1 v1.4.0 (outdated first simulation, up-to-date later), because the acceptance test compares top-level keys only.
- S2 Motor identity, as a sub-object `motors.identity` (one presence check for old manifests; `null` when the file has no motor): `designation` (e.g. `232H123-14A`), `manufacturer`, `ork_motor_type` (`reload`/`single`/`hybrid`…, verbatim), `config_id`, `motor_count` (motors in that configuration; identity describes the first one), `impulse_class` (the letter parsed from the designation, `null` when absent), `total_impulse_newton_seconds` (trapezoidal integral of the thrust curve the serializer already writes to `thrust_source.csv`, no rocketpy import; checked against the class range of `impulse_class`: A 1.26–2.5, B 2.51–5, C 5.01–10, D 10.01–20, E 20.01–40, F 40.01–80, G 80.01–160, H 160.01–320, I 320.01–640, J 640.01–1280, K 1280.01–2560, L 2560.01–5120, M 5120.01–10240, N 10240.01–20480, O 20480.01–40960; on mismatch the computed value is dropped to `null` and `impulse_check` = `class_mismatch`, else `ok`, or `unchecked` when no class), `burn_time_seconds` (burnout event time minus ignition event time of the reference simulation; else duration of thrust above 1 % of peak; `null` when neither exists). Missing values are `null`, never 0. The motor is the one in the reference simulation's configuration (fallback: the default configuration; fallback: the first motor, as today). The existing 14 physics keys and `position`/`thrust_source` are unchanged.
- S3 Provenance. `stored_results` gains `simulation_name`, `status` (`uptodate` | `outdated` | `loaded` | other verbatim | `null`), `config_id` (equal to `motors.identity.config_id`, asserted by a test), `selection` (S1); existing numeric keys keep "0 when missing" for backward compatibility (documented). `id` gains `ork_format_version` (the `<openrocket version>` attribute is the file-format version, not the app), `creator` (the app, e.g. `OpenRocket 24.12`) and `serializer_version` (this package's version via `importlib.metadata`). No new top-level key.
- S4 Web reads the new keys as optional. `lib/domain/rocket.ts`: `motor` becomes `{ designation, manufacturer, orkMotorType, impulseClass, totalImpulseNs, burnTimeS, propellantMassKg }` (all nullable; `totalImpulseNs` is the TypeScript name for newton-seconds, documented), `storedResults` gains `simulationName`, `status` (`"uptodate" | "outdated" | "loaded" | "unknown"`; `unknown` when the key is absent, i.e. old manifests) and `selection`; a legacy 0 apogee / max speed / flight time means "not available" (already ≤0 → null, now documented). Old manifests behave exactly as today (pinned by tests). `RocketSummaryCard` Motor row: "{manufacturer} {designation}" with a second line "{total impulse} N·s · {burn time} s burn · {propellant} kg propellant" (each part only when present; old manifests keep "{x} kg propellant" alone). Stored-results block: title "OpenRocket stored results · {simulation name}" with a pill `up to date` (ok) / `outdated` (warn) / `loaded` (neutral) / no pill when unknown; when the status is not `uptodate` the note reads "May not reflect the current design or settings; re-run the simulation in OpenRocket to refresh." `RunResults` OpenRocket row: "OpenRocket · {simulation name}{ · outdated}: apogee … · max speed … · flight time …", labelled on the row itself, never hidden, and never with a difference or % against RocketPy. Strings in both catalogs. Stub fixtures and `e2e/stub-api.mjs` carry the new keys for Icarus Mk II (Cesaroni Technology 232H123-14A, class H, impulse 232 N·s, up to date) and a second file with an `outdated` simulation; snapshots re-baselined from CI's Linux artifact.
- S5 Nothing else changes: `packages/icaro` reads the same 14 motor keys (extra keys ignored, pinned by its existing tests); the API passes the manifest through; old manifests in GCS keep working (S4 fallbacks). Docs: `packages/rocketserializer/README` (manifest keys, the `null` vs legacy `0` rule, the selection rule) and `apps/web/AGENTS.md` (rocket card fields) updated.
