# workbench-rocket-exports — Rocket/Export data model + tool-first Workbench UI

Objective: split today's API "rocket" (one Firestore doc per converted `.ork`) into **Rocket** (a team's rocket, groups files) and **Export** (one converted `.ork`), let a convert attach to an existing rocket, then rebuild `apps/web` around the Workbench concept approved in the design canvas (https://claude.ai/artifact/FahsifuwBqriCKVwBpcKxz, v14).
Branch `feat/workbench-rocket-exports` (from `main` 3908781). Delivery `feature-branch-chain` (user choice 2026-10-24): each slice is a PR against the feature branch, final PR to `main`. Runners: API `cd apps/api && uv run python -m pytest -m "not integration"`; web `cd apps/web && npm test` (vitest) + `npx tsc --noEmit` + `npm run lint` + `npm run i18n:check` + `npm run api:check`.
Forecast: ~3,800 authored changed lines → 5 slices (PR1 T1–T2 model+migration, PR2 T3–T4 API+client, PR3 T5–T6 theme+shell, PR4 T7 import states, PR5 T8–T9 results/compare/report + seam).

## Specs

- S1 Data model (`apps/api/icaro_api/services/db.py`). `ExportRecord` = today's `RocketRecord` fields renamed: `export_id` (== convert run_id), `rocket_id` (FK to `rockets`), `name`, `created_at`, `created_by`, `org_id`, `export_prefix`, `manifest`, `gcs_ref`, `ork_filename`, `has_source_ork`; Firestore collection `exports`, manifest NOT persisted (kept in GCS, as today). New `RocketRecord`: `rocket_id`, `name`, `org_id`, `created_by`, `created_at`; collection `rockets`. `SimRecord` gains `export_id` (the simulated export) and keeps `rocket_id` (its rocket, denormalized for "runs of this rocket"). `Db` Protocol, `InMemoryDb`, `FirestoreDb`: `save_rocket/get_rocket/list_rockets` (new meaning), `save_export/get_export/list_exports(org_id, rocket_id=None, limit, before)`, `list_simulations(org_id, rocket_id=None, …)`. Every read filtered by `org_id` in the Db layer (unchanged rule). Tests: `test_services_db.py`, `test_services_firestore_db.py`, `test_firestore_emulator.py` (integration) cover both records, FK filter, and that `exports` writes drop `manifest`.
- S2 Naming rule (user, 2026-10-24): the group is called **rocket** ("No usaría vehicle, al final esto es para cohetería universitaria y amateur"); the converted file is called **export** (matches existing `export_id`, `export_prefix`, `orgs/{org_id}/exports/{run_id}/`). No "vehicle"/"version" wording anywhere (code, API, UI copy).
- S3 Migration (`apps/api/icaro_api/scripts/migrate_rocket_exports.py`, same CLI shape as `backfill_org_id.py`: `--project`, `--database`, `--dry-run`, env fallbacks). Idempotent: for every `rockets/{id}` doc in the OLD shape (has `export_prefix`): write `exports/{id}` with `export_id=id`, `rocket_id=id` and all old fields; mark `rockets/{id}` with `schema_version: 2` and KEEP its legacy export fields (the pre-split API reads `export_prefix` from them during the migrate-then-deploy window and after a rollback); a later explicit `--drop-legacy-fields` pass removes `export_prefix`, `gcs_ref`, `ork_filename`, `has_source_ork`, `manifest` from marked docs only (revised per review finding R4-001, see L21). For every `simulations` doc without `export_id`: set `export_id = rocket_id`. Marked and new-shape docs are skipped and counted. Batches of ≤400 writes. `firestore.indexes.json` adds `exports (org_id ASC, created_at DESC)`, `exports (org_id ASC, rocket_id ASC, created_at DESC)`, `simulations (org_id ASC, rocket_id ASC, created_at DESC)`. `DEPLOY.md` and `apps/api/README.md` document the collections, indexes and the migration command. Tests: unit with the fake client pattern of `test_backfill_org_id.py` (old doc → export + rewritten rocket; new-shape doc untouched; simulation gains `export_id`; dry-run writes nothing) + emulator test alongside `test_backfill_org_id_emulator.py`.
- S4 API. `POST /api/convert` multipart accepts `file` and optional `rocket_id` form field. Without `rocket_id`: create a `RocketRecord` (name = `manifest["name"]`, fallback filename without `.ork`, `rocket_id = make_run_id()`) and the `ExportRecord` (`export_id = run_id`, same name). With `rocket_id`: 404 `Rocket '{rocket_id}' not found.` if absent or other org; otherwise only the export is created, attached to it. Response `{export_id, rocket_id, manifest}`. `GET /api/rockets` → `RocketSummary[]` (`rocket_id`, `name`, `created_by`, `created_at`). `GET /api/rockets/{rocket_id}` → `RocketDetail` = summary + `exports: ExportSummary[]` (`export_id`, `rocket_id`, `name`, `ork_filename`, `has_source_ork`, `created_by`, `created_at`, `export_prefix`, `gcs_ref`), newest first. New `GET /api/exports/{export_id}` → `ExportDetail` = `ExportSummary` + `manifest` read from `{export_prefix}parameters.json` (what `GET /rockets/{id}` returned before). `POST /api/simulate` keeps `export_id` in the body, resolves it with `get_export`, 404 `Export '{export_id}' not found.`, stores `SimRecord(export_id, rocket_id=export.rocket_id)`. `GET /api/history` rows add `export_id`, `rocket_name` (join-on-read via `get_rocket`) and `ork_filename`; optional query `rocket_id` filters. `GET /api/results/{run_id}` unchanged. Tests: router tests updated/added for each rule above, including the two 404 messages verbatim.
- S5 Web client adaptation (keeps today's UI working on the new API before the redesign): `npm run api:schema` + `npm run api:types` regenerate `openapi/schema.json` + `lib/api/schema.d.ts`; `lib/api.ts` exposes `convert(file, rocketId?)`, `getRockets`, `getRocket` (with exports), `getExport`; `WizardProvider` stores `rocketId` next to `exportId`; `RocketCard` "Use this rocket" loads the newest export of the rocket; `HistoryCard` re-runs with `item.export_id` (not `rocket_id`); `ReviewStep`/results show rocket name + export filename where the rocket name was shown. Tests updated to the new shapes; `npm run api:check` passes.
- S6 Theme (from the approved canvas; user 2026-10-24: "quiero que tenga un modo oscuro suave y un modo claro también pastel. No quiero negros y blancos"). `app/globals.css` defines the two palettes as CSS variables on `:root[data-theme="light"]` / `:root[data-theme="dark"]` with the canvas tokens (light bg `#F3F1F8`, surface `#FBFAFD`, ink `#2B2840`, accent `#6B7FE0`…; dark bg `#1E1D2A`, surface `#262535`, ink `#E6E3F2`, accent `#8E9CF2`…), no `#000`/`#fff`; Tailwind `@theme inline` maps them; a `ThemeProvider` + toggle persists the choice (cookie, like the locale) and respects `prefers-color-scheme` as the default; `layout.tsx` `themeColor` follows the theme; `AmbientBackground` adapts to both. Geist + Geist Mono stay; tabular numerals on numeric values.
- S7 Workbench shell (canvas board A; user 2026-10-24: "la idea del workbench me gusta. Vamos a profundizar en ella sin perder el norte con respecto a la plataforma original"). `/` renders the Workbench: left sidebar (Workbench, Rockets, Runs, theme toggle, account), top bar with the **rocket context button** (`{rocket name} · {export filename}`), status pill (`Up to date · run {id}` / `Results are from {filename} · run {id}` when the active export differs from the last run's) and `Run simulation` (⌘↵); inputs column (Launch site with map, Time & weather, Launch rail, Uncertainty presets) reusing the existing wizard domain logic (`lib/domain/scenario.ts`, validate/template/atmosphere/elevation calls) without the 4-step wizard; results column (S8). The old `WizardShell` routes stay reachable until T8 replaces them, then are removed.
- S8 `.ork` import states (canvas boards A1–A3; user 2026-10-24: "los chicos diseñan el cohete en openrocket, por lo que muchas veces tendrán que importar el .ork"; "Cada archivo es un cohete nuevo. Podríamos trabajar en que el usuario tengas varios cohetes, pero en este caso el usuario debería de elegir a consciencia a qué cohete pertenece el archivo que está subiendo"; "Metamos al alcance el que puedas relacionar un archivo a un cohete ya existente"). A1 no rocket: results column shows the `.ork` drop zone ("Drop your OpenRocket file here", `.ork` only, server conversion "can take up to a minute") and "Or pick one already converted" listing the org's rockets (name, newest export filename, author, date); inputs editable except rail/uncertainty, dimmed with "Defaults come from your .ork once it's loaded". A2 converting: top bar shows `{filename} converting…`, Run disabled, progress steps (Uploaded, Opened in OpenRocket, Exporting geometry & motor, Building the rocketpy model), KPI skeletons, and the **destination card** "Where does this file go?": radio "New rocket" (default, name field prefilled from the manifest name once known) vs "Add to one of my rockets" with a rocket select; nothing inferred from the filename; the choice is sent as `rocket_id` to `/api/convert` (so conversion starts after the choice, or the choice is made before upload completes — implementation detail, the user never has to guess). A3 rocket panel: clicking the rocket button opens a panel with the rocket's exports ("Files in this rocket", active-file radio, author, date, run count), "Compare two files", a drop zone "Drop a .ork to add it to {rocket}", other rockets as chips and "+ New rocket from .ork"; switching the active export marks results stale (S7 pill) and the Run button reads "Run this file".
- S9 Results, runs and report (canvas boards A/B/C). Results column: Flight replay = `Trajectory3D` restyled to the theme with play/pause, scrubber and speed, respecting reduced motion; 4 KPI cards (Apogee, Max speed, Stability off rail, Landing) with sparklines; series chart with metric tabs; flight timeline list. `/runs` (replaces `/history`): runs table per rocket with a baseline run, deltas, overlaid series, "What changed" chips, optional `rocket_id` filter. `/results/[runId]` restyled as the Run report (breadcrumb, replay hero, KPIs, warnings, All results / Configuration, plots, notes).
- S10 Cross-cutting: every visible string in `messages/en.json` + `es.json` (`npm run i18n:types`/`i18n:check`); `apps/web/AGENTS.md`/README note the Workbench + theme; `npm test`, `tsc`, `lint`, `build` green; API unit suite green; emulator suite green in CI. Assumption (mine, flagged): rocket "run count"/"export count" shown in lists are computed client-side from `/api/history?rocket_id=` and `RocketDetail.exports`, no denormalized counters.
