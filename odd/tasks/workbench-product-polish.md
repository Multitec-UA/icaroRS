Objective: redesign the Workbench end to end so the web, the API contract and the simulation core tell one story (Rocket → Scenario → Run), build a visual-regression net first, then execute the redesign on top of the delivered chain (base commit ccf3d25, tracker PR #113, children #114–#122).

Runners: web `cd apps/web && npm test` (vitest) + `npx tsc --noEmit` + `npm run lint` + `npm run i18n:check` + `npm run api:check` + `npm run build`; visual `cd apps/web && npm run e2e:visual` (Playwright, see S1); API `cd apps/api && uv run python -m pytest -m "not integration"`.

## Product model (the story every screen tells)

- **Rocket**: a team's design, from OpenRocket. It has files (exports, one per converted `.ork`). The active file carries the physics: mass, radius, motor, parachutes, rail defaults and OpenRocket's own stored results.
- **Scenario**: where, when and how the rocket is launched: site, date, atmosphere, rail. It is edited in the Workbench and sent verbatim to `POST /api/simulate`.
- **Run**: one simulation of one file under one scenario, by the core. It yields 16 scalars, 12 plots, the series and warnings. Runs are listed in `/runs`, each has a permanent report at `/results/{id}`.
- A scenario has no identity of its own in the API (no `/api/scenarios`): it lives inside a run. The UI never asks for a scenario name (`scenario.name` stays the API default) and never says "my scenarios".
- The Workbench is the editor for one (file, scenario) pair and shows the latest run of that pair. Its state is in the URL: `/?file={export_id}` while editing, `/?run={run_id}` once a run is shown, so refresh, back and shared links keep the state. `/rockets` is the garage. `/runs` is the logbook. The report is the printout. Every surface uses the same words, the same result components and loses nothing when you move between them.

## Specs

- S1 Visual net (before any UI change) plus behaviour flows (after the redesign). Playwright `@playwright/test` with Chromium in `apps/web/e2e/`: `playwright.config.ts` boots a stub API (`e2e/stub-api.ts`, plain Node `http`, deterministic fixtures: one org with two rockets, three files, four runs with real-looking scalars/series/warnings/plot names, auth `GET /api/auth/me` → signed in) on a free port, exported as `ICARO_API_ORIGIN` to `next build` + `next start` so both the browser fetches (`/api/*` rewrite) and the server fetches (`lib/server-api.ts`) hit it. Tests drive the real UI (no `vi.mock`), emulate `prefers-reduced-motion: reduce`, freeze `Date`/time zone via `page.clock` and `timezoneId: "Europe/Madrid"`, block map tiles (route `*.tile.openstreetmap.org/**` → a flat PNG), mask the WebGL replay canvas, and take `toHaveScreenshot` at 1440×900 in **both themes** (cookie `icaro-theme`) for: Workbench empty, Workbench converting (destination card), Workbench loaded without run, Workbench with result, Rocket panel open, `/rockets`, `/runs` (with compare overlay), `/results/{id}`, login. Snapshots live in `apps/web/e2e/__screenshots__/` and are generated inside the Playwright Docker image (`mcr.microsoft.com/playwright:v1.64.1-noble`) so local and CI pixels match: `npm run e2e:visual` (compare) and `npm run e2e:visual:update` (regenerate) both run through `e2e/run-in-docker.sh`; CI gets a `web-visual` job in `.github/workflows/test-icaro.yaml` on that image. The first commit of this feature is the net with baseline snapshots of the **current** UI, green. Stub fixtures are typed against `lib/api/schema.d.ts` (the generated OpenAPI types) so `tsc` fails when the contract drifts. After the redesign (T8), `e2e/flows.spec.ts` adds behaviour flows against the same stub: upload → destination → run → edit site → "Changed since run" chips → open `/runs` → "Open in Workbench" → state intact → browser back → draft intact; and a 404 run URL shows the S8 message.
- S2 One control system. `components/ui/` becomes the single token-based kit used by every screen: `Button` (primary / ghost / chip, 36 px, radius 9; under `pointer: coarse` the hit area grows to 44 px via padding/`min-height`), `StatusPill` (ok / warn / bad / neutral), `Field` + `TextInput` + `Select` (36 px), `Card`, `Disclosure`, `Kbd`. The legacy 48 px glass `Button`, `Surface`, `Eyebrow`, `Accordion`, `Callout` in `components/ui.tsx` and every literal colour (`bg-white/…`, `cyan-400`, `emerald-400`, `rose-400`, `from-white`) are removed; login (`AuthGate.tsx`), `/rockets`, `/runs`, the report and the Workbench all read tokens only. The light `--primary` becomes `#5160cc` so `--on-primary` text on it reaches 5.18:1 (WCAG AA needs 4.5:1 for 14 px text; today 4.43:1); `--accent-ink`, `--ok-ink`, `--warn-ink`, `--bad-ink` on their soft backgrounds are checked the same way and the results recorded in `design/system.md`. `rg -n "white/|cyan-|emerald-|rose-|#fff|#000" apps/web/components apps/web/app` returns nothing.
- S3 Rocket identity. `lib/domain/rocket.ts` derives a `RocketSummary` view from `ConvertResult.manifest` / `ExportDetail.manifest`: name (`id.rocket_name`), file, dry mass (kg), liftoff mass, radius → diameter (mm), motor as propellant mass (the serializer emits no designation or total impulse: `rocketserializer/components/motor.py:75-90`, amended 2026-10-31), parachutes (count, names), rail defaults (`manifest.flight.rail_length`, `inclination`, `heading`), and OpenRocket's stored results (apogee, max velocity, flight time) when present. A `RocketCard` component shows it (a) in the results column when a file is loaded and nothing has run ("Ready to run" state, replacing the dashed placeholder), (b) in the Rocket panel per file (compact), (c) in the report's Configuration section. Missing manifest fields render as "—", never as `undefined`/`NaN`.
- S4 Rail and atmosphere are honest. `LaunchRailSection` prefills length / inclination / heading from the active file's rail defaults (`manifest.flight`; the serializer already converts OpenRocket's rod angle to RocketPy's inclination from horizontal, `rocketserializer/components/flight.py:34`) with a "From .ork" badge; the inclination field states the convention ("90° = vertical"); an edited field shows "Overridden" and a "Reset" link that restores the file value. The request sends a `rail` key **only for overridden fields** (never the prefilled defaults), so Reset truly resets and switching files does not carry old values silently; overrides survive a file switch and show as "Overridden" against the new file's defaults. The dimmed fieldset and the note "Defaults come from your .ork once it's loaded" disappear. With no file loaded the rail fields show the placeholder "From your .ork" and stay disabled, but the rest of the inputs are fully editable. `TimeWeatherSection` exposes `atmosphere.fallback` as a "If the forecast is unavailable" select offering the values the API accepts (today only `standard_atmosphere`: `simulation.py:209` passes the value to `env.set_atmospheric_model`, there is no "fail" value; amended 2026-10-31) with the help line "A fallback is always reported as a warning on the result."; when the core falls back it emits a warning (`icaro/simulation.py:202`) that the result shows in the Warnings banner and the report, so a silently different atmosphere is impossible (verified: `routers/simulate.py:129` records warnings into the result). The `reanalysis` file path field is removed from the UI (server-side path, never user input) and the model select offers only `forecast`, `wyoming_sounding`, `standard_atmosphere`.
- S5 Uncertainty leaves the Workbench. The simulate use-case ignores `scenario.uncertainty` (`packages/icaro/icaro/simulation.py`; `run_monte_carlo` is not wired), so the Uncertainty presets section, its glossary copy ("feeds the dispersion / landing-spread analysis"), its mention in the report Configuration and `WhatChanged`, and its tests are removed; the request body sends `uncertainty: {}`. No "coming soon" teaser. Monte Carlo is a separate future feature (logged, not built here).
- S6 Stale is real. The reference is the **displayed run** (`export_id` + its stored `scenario`, whether it came from a fresh run or from `/runs` via S8), never loose in-memory state. `lib/domain/scenario.ts` gains `canonicalScenario(body)`: sorted keys, coordinates rounded to 5 decimals, elevation to 1, rail keys only when overridden, `uncertainty` dropped; the status pill compares the canonical current body with the canonical displayed-run body: "No run yet" (neutral), "Running…" (neutral, with spinner), "Up to date · run {id}" (ok), "Changed since run {id}" (warn) with chips naming what changed (file, site, date, weather, rail), reusing the `WhatChanged` chip component of `/runs`. Run is disabled while a run is in progress; edits made during a run are kept and the arriving result shows immediately as "Changed since run {id}". The Run button reads "Run simulation" before the first run and "Run again" afterwards; it is never disabled only because nothing changed (a forecast atmosphere can yield different numbers later).
- S7 Results are the same object everywhere. `components/results/RunResults.tsx` is the one composition: Warnings → FlightReplay (or skeleton / "no series") → KPI cards (Apogee, Max speed, Stability off rail, Landing) → one comparison row "OpenRocket, its own conditions saved in the file: apogee {v} · max speed {v} · flight time {v}" when `stored_results` has them (never per KPI card, never implying RocketPy is off by X%) → Series panel → Flight timeline → `Disclosure` "All results (16 values)" (the scalar table) → `Disclosure` "Plots (12)" (the PNG gallery, always available, lazy; each PNG sits in a light framed card so matplotlib's white background does not glare in the dark theme). The Workbench results column and the report page both render `RunResults`; the report adds breadcrumb, header and Configuration (scenario + `RocketCard`) and has print CSS (`@media print`: disclosures expanded, replay replaced by the `trajectory_3d` PNG, sidebar hidden). The PNG-only-on-series-failure branch is removed.
- S8 Lossless navigation. A run row in `/runs` and the report header offer "Open in Workbench" = navigate to `/?run={id}`; the Workbench resolves the URL on mount: `GET /api/history/{id}` → scenario + `export_id` + result, `GET /api/exports/{export_id}` → manifest, rocket name and file; it shows "Up to date · run {id}". A missing run or file (404) shows a clear message in the results column ("This run's file is no longer available"), never a blank Workbench. Unsaved edits are not lost: the browser back button returns to the previous `/?file=…` URL with the draft still in memory. "Re-run" on `/runs` becomes "Open in Workbench" (no silent new run); "Simulate again" on the report is the same action. A run started in the Workbench keeps running server-side if the student navigates away and lands in `/runs` anyway (the API writes the run on completion); the Workbench shows a toast "Run {id} finished" with a link when the mutation resolves on another route. The wizard remnants (`step`, `STEP_ORDER`, `goto/next/back`, `canAdvance`, `validateScenario`, `useResultQuery`) are deleted along with the `review.*`, `basics.*`, `advanced.*` i18n namespaces; Workbench copy lives under `workbench.*`, `rocket.*`, `runs.*`, `report.*`.
- S9 Import is always reachable. The TopBar rocket button opens the Rocket panel whenever a file is active, including legacy exports without `rocket_id` (panel shows the file alone with "This file isn't in a rocket yet" and the import drop zone; no migration wording). The panel is the single import place once a file is active; the results column keeps the big drop zone only in the empty state; dropping a `.ork` anywhere on the Workbench (`WorkbenchShell` drag-over overlay) opens the destination card. Converting state and destination card unchanged in behaviour; the error tone comes from the HTTP status (`503` → warn "The converter is unavailable right now", `4xx` → bad with the server detail), never from the `"java"` substring.
- S10 Layout holds at every width, results first on phones. Below 1024 px the Workbench becomes two tabs, "Inputs" and "Result", opening on Result when a run exists or when no file is loaded yet (importing is the first thing a phone shows; amended 2026-11-01 after T7), on Inputs once a file is loaded and nothing has run, and switching to Result when a new run is displayed; the sidebar becomes a bottom bar (Workbench, Rockets, Runs, account) instead of an icon rail; the TopBar keeps context + status dot + Run on one row. `/results/{id}` is the page that must be excellent on a phone (shared links): single column, replay full-width, KPIs 2×2, disclosures collapsed. Visual snapshots at 390×844 for Workbench-with-result and the report join S1.
- S11 Cross-cutting: every string in `messages/en.json` + `es.json` (`i18n:check`), `apps/web/README.md` + `AGENTS.md` describe the product model and the visual net; vitest, tsc, lint, i18n, api:check, build and the visual suite green; API unit suite untouched and green (no API change is planned; if S8 needs `GET /api/history/{id}` fields it already returns `scenario` and `export_id`).

- S12 Judge round 2 corrections (2026-11-01, from L15): (a) `/runs` "What changed" uses `scenarioDiff` over canonical bodies (groups file, site incl. elevation, date, weather incl. fallback, rail), replacing the narrower `whatChanged`; its tests are rewritten to the new output. (b) A rail override equal to the file default is stored as no override (badge back to "From .ork"). (c) The atmosphere fallback is a sentence "If the forecast is unavailable, the standard atmosphere is used and the run says so." with no select while the API accepts one value. (d) Inclination hint adds "= {90 − value}° from vertical in OpenRocket". (e) With the Forecast model, a date more than 16 days ahead or in the past shows a notice under the date before running: "Outside the forecast window: the run will fall back to the standard atmosphere." (f) A disabled Run button carries the reason (title + visible helper): missing site / missing date / running. (g) The finished-run toast reads "{rocket} · apogee {value} · Open". (h) The report's copy-link control reads "Copy link · visible to members of {org}". (i) The report renders when `GET /api/exports/{id}` fails: results and scenario stay, the rocket card shows "File no longer available", only "Open in Workbench" is disabled. (j) Phones: no tabs until a file is loaded (the results column fills the screen with the drop zone and the picker); once a file is loaded the tabs appear opening on Inputs; pressing Run switches to Result; a result arriving later never switches tabs. (k) The drop zone shows a visible "Choose .ork file" button (always, not only on coarse pointers). (l) Edits made after a run survive a refresh: the draft scenario is kept in `sessionStorage` keyed by export id and re-applied after `/?run=` resolves, so the pill reads "Changed since run {id}" again.
