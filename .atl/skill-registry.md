## Skill scoping (read before resolving)

Every project in the monorepo carries its own skills. Nested `.claude/skills/`
directories load **on demand** — only when the sub-agent touches files under that
project. Unused projects cost zero context.

| Level | Location | Applies to |
|-------|----------|-----------|
| Personal | `~/.claude/skills/` | every project |
| Project | `.claude/skills/` | all of icaroRS |
| Nested | `<project>/.claude/skills/` | only work under that project |

**Resolution rule for delegators:** match the sub-agent's target path to its project,
inject that project's skills plus the personal + root ones. Never inject `apps/web`
design skills into `packages/**` work, or Python skills into web work.

### Two installation mechanisms live side by side

1. **Curated (manual, real directories).** `apps/web/.claude/skills/<name>/SKILL.md` —
   the 12 design skills, relocated from the repo root. Plain directories, git-tracked.
2. **autoskills (`npx autoskills`, symlinked).** Real content at
   `<project>/.agents/skills/<name>/SKILL.md`; `<project>/.claude/skills/<name>` is a
   **relative symlink** to it (`../../.agents/skills/<name>`).

Both work. Claude Code documents the symlink form explicitly: *"A `<skill-name>` entry
in the enterprise, personal, or project locations can be a symlink to a directory
elsewhere on disk. Claude Code follows the symlink and reads `SKILL.md` from the target
directory."* The `.agents/` copy is tool-agnostic — other agent CLIs read it directly.

**Manifests are per-directory.** Each project has its own `skills-lock.json` next to its
`.claude/`. Verified: `npx autoskills` run inside a project reads and merges that
project's manifest and leaves the others untouched. Add new entries to the manifest in
the SAME directory tree as the skill.

⚠️ **Windows caveat:** the autoskills symlinks are committed. A Windows checkout without
`core.symlinks=true` / Developer Mode turns each one into a text file containing the
target path, and Claude Code loses the skill. The `.agents/` content still resolves for
tools that read it directly. Windows contributors should re-run `npx autoskills` locally.

## Flags (unresolved — human decision pending)

### `python-executor` sends code to a third-party service
Installed in **5 of 6 projects** (`apps/api`, `apps/cli`, `packages/icaro`,
`packages/rocketpy`, `packages/rocketserializer`). Despite the name, it is **not a local
sandbox**: it ships code to **inference.sh** through their `belt` CLI
(`belt app run infsh/python-executor`), and its frontmatter pre-authorizes
`allowed-tools: Bash(belt *)`.

For a private Multitec repo this is an outbound path for proprietary flight-simulation
code. It requires `belt login`, so it cannot run silently without an account — but an
agent will try if the trigger matches ("python", "run script", "data analysis"), which is
a very broad trigger set. **Decide explicitly whether to keep it.**

### Web-quality skills on a physics library
`packages/rocketpy` carries `accessibility`, `frontend-design`, and `seo`. It is a 6-DOF
flight-simulation library. The only HTML in the package is
`docs/matlab/Getting_Started.html`, a generated MATLAB doc export — not a reason for WCAG
or SEO tooling. Delegators should **not** inject these for `packages/rocketpy` work.

### `branch-pr` describes automation this repo does not have
See the `branch-pr` compact rules below — no `type:*` labels, no PR-validation workflow.

## Compact Rules

Pre-digested rules per skill. Delegators copy matching blocks into sub-agent prompts
as `## Project Standards (auto-resolved)`.

### branch-pr
- Every PR MUST link an approved issue in the body: `Closes #N` / `Fixes #N`.
- Branch regex: `^(feat|fix|chore|docs|style|refactor|perf|test|build|ci|revert)\/[a-z0-9._-]+$`.
- Commit regex: `^(build|chore|ci|docs|feat|fix|perf|refactor|revert|style|test)(\([a-z0-9\._-]+\))?!?: .+`.
- Scope by area when useful: `feat(icaro): …`, `fix(serializer): …`, `refactor(monorepo): …`.
- NEVER add `Co-Authored-By` or AI attribution to commits.
- **icaroRS DEVIATION — do not follow blindly:** the skill mandates exactly one `type:*`
  label and four PR-validation CI checks. icaroRS has **no `type:*` labels** and **no
  PR-validation workflow**. Attempting `gh pr edit --add-label "type:feature"` fails.
- Use the labels that actually exist (see `issue-creation` below). The issue→approval
  gate here is a `CONTRIBUTING.md` convention enforced by humans, not by Actions.

### issue-creation
- Blank issues are disabled — always use a template.
- Templates present: `.github/ISSUE_TEMPLATE/{bug_report.yml,feature_request.yml,config.yml}`.
- Creation auto-labels `bug`|`enhancement` + `status:needs-review`.
- A maintainer must add `status:approved` before any PR is opened.
- Open-ended questions go to Discussions, never issues.
- Search duplicates first: `gh issue list --search "keyword"`.
- **Labels that exist in icaroRS:** `bug`, `enhancement`, `documentation`, `duplicate`,
  `good first issue`, `help wanted`, `invalid`, `question`, `wontfix`,
  `status:needs-review`, `status:approved`, `priority:high|medium|low`. Nothing else.

### judgment-day
- Launch TWO blind judge sub-agents in PARALLEL, never sequential. The orchestrator
  coordinates only — it never performs the review itself.
- Resolve skills from this registry first; inject the same `## Project Standards
  (auto-resolved)` block into BOTH judges AND the fix agent.
- Synthesis: found by both → Confirmed; by one → Suspect; disagreement → Contradiction.
- Classify every warning: **real** (a normal user can trigger it) vs **theoretical**
  (contrived input/timing). Theoretical warnings are reported as INFO — never fixed,
  never re-judged, never counted toward convergence.
- Round 1: present the verdict table and ASK before fixing.
- Round 2+: re-judge only for confirmed CRITICALs. Fix real WARNINGs inline without
  re-launching judges.
- APPROVED = 0 confirmed CRITICALs + 0 confirmed real WARNINGs.
- After 2 fix iterations with issues remaining → ask the user whether to keep iterating.

### skill-creator
- Frontmatter required: `name`, `description` (must embed `Trigger: …`),
  `license: Apache-2.0`, `metadata.author`, `metadata.version` (string).
- Layout: `skills/{name}/SKILL.md`, optional `assets/` (templates, schemas) and
  `references/` (**local paths only**, never web URLs).
- Naming: `{technology}` | `{project}-{component}` | `{action}-{target}`.
- Body order: When to Use → Critical Patterns → Code Examples → Commands → Resources.
- Do NOT add a Keywords section, duplicate existing docs, or add troubleshooting.
- Register the new skill in `AGENTS.md`.
- **icaroRS placement:** frontend/design skills → `apps/web/.claude/skills/`;
  repo-wide skills → `.claude/skills/`. Add the matching `skills-lock.json` entry to
  the manifest in the SAME directory tree.

### full-output-enforcement
- Never emit `// ...`, `// TODO`, `// rest of code`, `// implement here`, or bare `...`
  standing in for real code.
- Never write "for brevity", "the rest follows the same pattern", "and so on",
  "let me know if you want me to continue".
- Count the deliverables the request implies, lock that number, verify the count before
  responding.
- Never ship a skeleton when a full implementation was requested; never show first and
  last section while skipping the middle.
- On approaching the token limit: stop at a clean breakpoint and emit
  `[PAUSED — X of Y complete. Send "continue" to resume from: <section>]`. Never compress.
- Code blocks must contain runnable code, not prose describing what the code would do.

### design-taste-frontend
- Default taste skill (v2). Emit a one-line "Design Read" before generating anything.
- Dials: variance 8, motion 6, density 4 — adapt to the brief.
- Stack: React/Next with RSC by default. Tailwind **v4** unless the project demands v3
  (for v4 use `@tailwindcss/postcss`, not the `tailwindcss` postcss plugin).
- Animation: import from `motion/react`, not `framer-motion` (legacy alias).
- NEVER `useState` for continuous input (mouse position, scroll progress, pointer
  physics) — use `useMotionValue` / `useTransform` / `useScroll`.
- Icons: `@phosphor-icons/react`, `hugeicons-react`, `@radix-ui/react-icons`,
  `@tabler/icons-react`. Discouraged: `lucide-react`. Never hand-roll SVG icons.
  One family per project. Standardize `strokeWidth`.
- Verify `package.json` before importing ANY dependency; print the install command first.
- Hero hard rules: fits the initial viewport, headline ≤2 lines, subtext ≤20 words and
  ≤4 lines, top padding ≤ `pt-24`, max 4 text elements total. Trust logos go BELOW.
- Max **1 eyebrow per 3 sections** (the most-violated rule). Split-header pattern banned
  by default. Max 2 consecutive image+text zigzag sections.
- Bento cells must exactly match content count — no blank tiles. ≥2-3 cells need real
  visual variation (image, pattern, tinted bg), not white-on-white typography.
- `min-h-[100dvh]` never `h-screen`. CSS Grid, never flex percentage math.
  Declare the `<768px` collapse explicitly per section.
- **icaroRS:** `apps/web` is Next **16.2.6** + React **19.2.4**. Read
  `apps/web/AGENTS.md` first — Next 16 has breaking changes vs training data.

### design-taste-frontend-v1
- Legacy v1, kept only for exact backward compatibility. Prefer `design-taste-frontend`.
- Same dials (8/6/4) and anti-slop core as v2, with these v1 specifics:
- Banned visuals: `Inter`, pure `#000000`, neon/outer glows, oversaturated accents,
  gradient text on large headers, custom mouse cursors.
- Banned layout/content: 3-equal-column card rows, centered heroes when variance > 4,
  "John Doe"/"Acme"/"Nexus", fake round numbers (`99.99%`, `50%`), AI clichés
  ("Elevate", "Seamless", "Unleash", "Next-Gen").
- Emoji policy is ABSOLUTE in v1 (v2 softened it to "discouraged, override on request").
- Icons: exactly `@phosphor-icons/react` or `@radix-ui/react-icons`.
- Never mix GSAP/ThreeJS with Framer Motion in the same component tree. Framer for UI,
  GSAP/ThreeJS only for isolated scrolltelling or canvas, with strict useEffect cleanup.
- Placeholders: `https://picsum.photos/seed/{seed}/800/600`. Never Unsplash.

### gpt-taste
- Before ANY UI code, output a `<design_plan>` with a simulated deterministic Python RNG
  selecting: 1 hero architecture, 1 type stack, 3 component architectures, 2 GSAP paradigms.
- Fonts: Satoshi, Cabinet Grotesk, Outfit, or Geist. NEVER `Inter`.
- AIDA structure: premium nav → hero → bento → GSAP scroll → CTA/footer.
  Section spacing `py-32 md:py-48`.
- H1 iron rule: max 2-3 lines. Use `max-w-5xl`/`max-w-6xl` with
  `clamp(3rem, 5vw, 5.5rem)`. Four or more lines is a hard failure.
- Bento grids MUST use `grid-flow-dense` with mathematically interlocking spans.
  Zero empty cells. 3-5 intentional cards, never 8 messy ones.
- Real GSAP required (`@gsap/react`, ScrollTrigger): pinning, scrubbed text reveals,
  card stacking, image scale-and-fade on scroll.
- BANNED: meta-labels ("SECTION 01", "QUESTION 05"), hero stamp badges, hero pill-tags,
  raw stats in the hero, emojis anywhere in code or output.
- Wrap the page in `<main className="overflow-x-hidden w-full max-w-full">`.

### high-end-visual-design
- Banned: `Inter`/`Roboto`/`Arial`/`Open Sans`/`Helvetica`; Lucide/FontAwesome/Material
  icons; 1px solid gray borders; `shadow-md` and harsh dark shadows; edge-to-edge sticky
  navbars; symmetrical 3-column grids; `linear`/`ease-in-out` transitions.
- Pick 1 Vibe archetype (Ethereal Glass / Editorial Luxury / Soft Structuralism) AND
  1 Layout archetype (Asymmetrical Bento / Z-Axis Cascade / Editorial Split) per build.
- Double-Bezel mandatory on cards: outer shell (`ring-1`, `p-1.5`, `rounded-[2rem]`) +
  inner core with concentric radius `rounded-[calc(2rem-0.375rem)]` and inset highlight.
- CTA buttons: `rounded-full`; a trailing arrow lives inside its own circular wrapper,
  never naked beside the text.
- Section padding `py-24` to `py-40`. Transitions use custom curves, e.g.
  `ease-[cubic-bezier(0.32,0.72,0,1)]`.
- Scroll entry via `IntersectionObserver` or `whileInView` — never
  `window.addEventListener('scroll')`.
- Animate only `transform`/`opacity`. `backdrop-blur` only on fixed/sticky elements.
  `min-h-[100dvh]`, never `h-screen`.
- Below 768px every asymmetric layout collapses to `w-full px-4 py-8`; drop rotations
  and negative-margin overlaps (touch-target conflicts).

### minimalist-ui
- Warm monochrome editorial. Banned: `Inter`/`Roboto`/`Open Sans`; Lucide/Feather/
  Heroicons; `shadow-md`+; gradients; neon; 3D glassmorphism; `rounded-full` on large
  containers; emojis; "John Doe"/"Acme"/Lorem Ipsum; AI clichés.
- Fonts: SF Pro Display / Geist Sans / Switzer (UI); Lyon Text / Newsreader /
  Instrument Serif (headings, tracking `-0.02em`→`-0.04em`, line-height `1.1`);
  Geist Mono / JetBrains Mono (metadata).
- Body text never `#000000` — use `#111111` or `#2F3437`, line-height `1.6`;
  secondary `#787774`.
- Canvas `#FFFFFF` or warm bone `#F7F6F3`. Borders exactly `1px solid #EAEAEA`.
  Card radius 8-12px max, padding 24-40px.
- Accents only as washed pastels: `#FDEBEC`/`#E1F3FE`/`#EDF3EC`/`#FBF3DB` with their
  paired dark text colors.
- Primary CTA: `#111111` bg, white text, radius 4-6px, no shadow, hover `#333333` or
  `scale(0.98)`.
- Icons: Phosphor (Bold/Fill) or Radix. Standardize stroke width.
- Motion invisible: `translateY(12px)` + opacity over 600ms
  `cubic-bezier(0.16, 1, 0.3, 1)`, `IntersectionObserver` only, 80ms stagger.
- Section padding `py-24`/`py-32`; typographic content `max-w-4xl`/`max-w-5xl`.

### industrial-brutalist-ui
- Pick ONE archetype per project and commit to it: Swiss Industrial Print (light) OR
  Tactical Telemetry / CRT (dark). Never mix substrates in one interface.
- Swiss light: bg `#F4F4F0`/`#EAE8E3`, fg `#050505`-`#111111`, accent `#E61919`/`#FF2A2A`
  (the only accent).
- Tactical dark: bg `#0A0A0A`/`#121212` (never pure black), fg `#EAEAEA`, same red.
  Terminal green `#4AF626` for at most ONE specific element, or omit it.
- Macro type: Archivo Black / Neue Haas Grotesk / Monument Extended,
  `clamp(4rem, 10vw, 15rem)`, tracking `-0.03em`→`-0.06em`, line-height `0.85`-`0.95`,
  uppercase.
- Micro type: JetBrains Mono / IBM Plex Mono / Space Mono, 10-14px,
  tracking `0.05em`-`0.1em`, uppercase.
- Absolute rejection of `border-radius` — every corner is 90°.
- Grid trick: `display: grid; gap: 1px` with a contrasting parent background for
  razor-thin dividers without border declarations.
- ASCII framing (`[ LABEL ]`, `>>>`, `///`), ®/©/™ as structural elements, crosshairs at
  grid intersections, barcode rules, `REV 2.6`-style fake telemetry strings.
- Analog degradation: halftone / 1-bit dithering, CRT scanlines via
  `repeating-linear-gradient`, global low-opacity SVG noise on the root.
- Semantic tags: `<data>`, `<samp>`, `<kbd>`, `<output>`, `<dl>`.
- No gradients, no soft drop shadows, no modern translucency.

### redesign-existing-projects
- Sequence: **Scan** (detect framework + styling method) → **Diagnose** (list every
  generic pattern found) → **Fix** (targeted, inside the existing stack).
- Never migrate frameworks or styling libraries. Never rewrite from scratch. Keep
  changes small and reviewable. Test after every change.
- Check `package.json` before importing anything. Check the Tailwind version (v3 vs v4)
  before touching config.
- Fix priority: fonts → color cleanup → hover/active states → layout & spacing →
  replace cliché components → loading/empty/error states → typography polish.
- Kill the AI fingerprints: purple/blue gradient aesthetic, pure `#000000`, more than one
  accent, mixed warm/cool grays, 3 equal card columns, Lucide/Feather icons,
  `height: 100vh`, Lorem Ipsum, "John Doe"/"Acme", "Elevate"/"Seamless"/"Unleash".
- Add what AI forgets: focus rings, skeleton loaders, empty states, inline form errors,
  custom 404, legal links, skip-to-content, favicon, meta/og tags.
- Alignment discipline: pin card CTAs to a shared baseline, start feature lists at the
  same Y across columns, use optical (not mathematical) centering.

### image-to-code
- Image-first is MANDATORY for visually important web work: generate the design image(s)
  → analyze deeply → extract the design system → only then implement.
- Never start with freeform coding. Never rely on remembered "good frontend taste"
  instead of producing the actual reference.
- Prefer many large, readable, section-specific images over one compressed board.
  Never crop old images — generate fresh standalone ones.
- Better too many clear images than too few unreadable ones. Never cut image count for
  convenience.
- Anti-nested-box rule: no cards inside cards inside cards; no giant rounded section
  containers everywhere.
- Reduce micro-UI clutter: fewer pills, tags, tiny labels, fake system markers.
- Hero stays clean, spacious, readable, and fully visible on a small laptop.
- The image is the design source; the code is the translation layer.

### imagegen-frontend-web
- PRIMARY RULE: **one separate horizontal image PER section.** Never combine sections,
  never a single tall full-page image, never one "best" image with the rest skipped.
- Ambiguous counts default high: "hero" → 1; "landing page"/"product page"/"portfolio"
  → 6; "full website"/"marketing site"/"site template" → 8.
- If only one image renders per call, emit them sequentially in the same response,
  labeled "Section X of N: <name>", until the set is complete.
- Format always horizontal: 16:9 or 21:9 for hero, 16:10 for narrower sections.
- Hero composition bias: left-text/right-image is the most overused AI pattern. Consider
  centered-over-image, bottom-left, image-as-canvas, off-grid editorial, mini minimalist,
  or inverted classic first.
- Vary CTA style, hero scale, background mode, and composition anchor across sections
  while keeping ONE consistent palette for the whole set.
- Generates images only — it does not write code.

### imagegen-frontend-mobile
- Mobile app screens ONLY. Explicitly NOT for websites, landing pages, desktop
  dashboards, image-to-code, or code generation.
- Pick a platform mode: iOS-native premium, Android-native premium, or cross-platform
  neutral — then stay consistent.
- Screens render inside a subtle premium phone mockup by default, with the app content
  as the focus, not the frame.
- Enforce multi-screen consistency and a logical flow. Never clone screens.
- Respect safe areas and system regions. Keep the first screen clean.
- Banned visual tells: purple-blue fintech gradients, random glass cards, purposeless
  ambient blobs, fake neon, dribbble floating widgets, oversized radii on everything.
- Banned layout tells: fake chart/stat-card spam, 12 widgets fighting for attention,
  phone-shaped websites instead of app screens.
- Banned copy: "elevate your life", "unlock your potential", "next-gen finance",
  "seamless control"; fake brands Acme / NovaCore / Flowbit / Quantix / VeloPay.
- Banned clutter: too many pills, badges, tiny labels, meaningless avatar rows,
  decorative toggles with no product meaning.
- **Note for icaroRS:** there is no mobile app in this repo. This skill is available
  under `apps/web` for concept work only.

### brandkit
- A brand kit is a visual argument for why the brand exists, not decoration. Infer the
  brand strategy BEFORE generating anything.
- Default output: one overview image, `3 × 3` grid, aspect `4:3` or `16:10`, consistent
  gutters, minimal text, every panel visually connected.
- Allowed layouts: `3×3` full identity, `2×3` cinematic deck, `2×2` compact concept,
  `1×3` strip, `4×2` contact sheet.
- The logo must be simple, memorable, symbolic, scalable, ownable, and usable as icon,
  wordmark, badge, UI mark, and pattern.
- Logo bans: generic lightning bolts, random animals, fake luxury crests, copied famous
  marks, overcomplicated symbols, clipart icons, meaningless sparkles, inconsistent
  variants.
- Logo concept methods: monogram + meaning, product action, metaphor fusion, negative
  space, construction geometry.
- Given references, match their quality and rhythm — never their exact content.
- Generates images only.

### stitch-design-taste
- Output is a `DESIGN.md` for Google Stitch, not code.
- Encode seven blocks: atmosphere, color (hex + functional role), typography, component
  behaviors, layout, motion, anti-patterns.
- Default dials: variance 8, motion 6, density 4.
- Max 1 accent, saturation < 80%. AI purple/blue neon BANNED. Never pure `#000000`.
  One palette throughout — no warm/cool gray drift.
- Fonts: `Inter` BANNED for premium contexts — use Geist / Outfit / Cabinet Grotesk /
  Satoshi. Generic serifs banned; dashboards are sans-only. Density > 7 → monospace
  numbers.
- Hero: inline image typography is the signature technique. No overlapping elements, no
  "Scroll to explore"/chevrons, max 1 primary CTA. Centered heroes banned when
  variance > 4.
- Layout: no 3-equal-card rows, CSS Grid over flex math, max-width ~1400px,
  `min-h-[100dvh]` never `h-screen`.
- Motion: spring `stiffness: 100, damping: 20`, staggered reveals, perpetual micro-loops,
  `transform`/`opacity` only.
- Responsive: single column < 768px, 44px touch targets, `clamp()` headlines, zero
  horizontal overflow.
- Be descriptive AND precise: "Deep Charcoal Ink (#18181B)", never just "dark text".

  Listed for completeness; do not inject it into sub-agent prompts here.
- If it ever becomes relevant: table-driven tests, Bubbletea model testing, `teatest`

## Project Compact Rules (by area)

### Python / RocketPy core (`packages/rocketpy/**`)
- `requires-python >= 3.10`; Ruff `target-version = "py310"`, `line-length = 88`.
- Format and lint with **Ruff** (`ruff format`, `ruff check`). Docstrings: NumPy style.
- Scientific precision: validated against real flights (EPFL, NDRT). Do NOT introduce
  approximations or hardcoded physical constants without rigorous justification.
- Performance-sensitive: core calculations run thousands of times in Monte Carlo.
- Preserve the public API flow `Environment → Motor → Rocket → Flight`.
- If you change drag, thrust, or wind-interpolation formulas, tell the user to run the
  suite and check for trajectory regressions.
- Full context: `packages/rocketpy/AGENTS.md`.

### Python / RocketSerializer (`packages/rocketserializer/**`)
- `requires-python >= 3.8` (wider than the rest of the repo — do not use 3.10+ syntax).
- Format with **Black** (line-length 88) + **isort** (`profile = "black"`).
  Lint with **Pylint** (`max-line-length = 88`).
- **Gotcha (still present):** `rocketserializer/__init__.py` line 1 is
  `from .ork_extractor import ork_extractor`, which **rebinds the package attribute from
  module to function**. To `mock.patch` attributes on that module, retrieve it via
  `sys.modules["rocketserializer.ork_extractor"]` — `import as` and dotted-string paths
  resolve to the function and fail with `AttributeError`.
- Acceptance tests are JVM-bound: need Java 21 + `packages/rocketserializer/OpenRocket-23.09.jar`
  (path is working-directory relative).

### Python / icaro domain + API (`packages/icaro/**`, `apps/api/**`)
- Both `requires-python >= 3.10`. `apps/api` sets `asyncio_mode = "auto"`.
- Both declare a pytest marker `integration` — "require JVM/network/real files, skip in CI".
  Unit runs use `-m "not integration"`.
- Business logic belongs in `packages/icaro` as use-cases; `apps/api` stays a thin
  adapter. Packages return objects, they never print or format — use `warnings.warn`
  for advisories and let the surface present them.
- API run: `ICARO_BASIC_USER=… ICARO_BASIC_PASS=… ICARO_ORK_JAR=packages/rocketserializer/OpenRocket-23.09.jar uv run uvicorn icaro_api.main:app --port 8000 --workers 1`.

### Web (`apps/web/**`)
- Standalone **npm** project — NOT a uv workspace member. Never run `uv` here.
- Next **16.2.6**, React **19.2.4**, TypeScript **^5**, ESLint.
- `apps/web/AGENTS.md` warns: this is NOT the Next.js in your training data. Read the
  relevant guide in `node_modules/next/dist/docs/` before writing code. Heed deprecations.
- Checks: `npm run lint`, `npx tsc --noEmit`, `npm run build`.
- Dev needs the API running first (dev proxy). See `apps/web/README.md`.

### Testing
- Runner: **pytest** everywhere on the Python side.
- Core suites must run **from their own directory** — fixtures use relative paths.
  - `cd packages/rocketpy && uv run pytest tests/{unit,integration,acceptance}`
  - `cd packages/rocketserializer && uv run pytest tests/{unit,acceptance}`
- Domain + API (no JVM/network):
  - `uv run python -m pytest packages/icaro/tests`
  - `cd apps/api && uv run python -m pytest -m "not integration"`
- Install everything: `uv sync` (editable, cross-linked).
- RocketPy sensitivity tests need the `monte-carlo` extra (`statsmodels`).

### CI (GitHub Actions — `.github/workflows/`, 3 workflows)
- `test_pytest.yaml` — **RocketPy core**. Paths: `packages/rocketpy/{rocketpy,tests,data}/**`,
  its `pyproject.toml`/`requirements*`. Matrix py3.10 / 3.12. Runs unit (with `--cov`),
  doctests, integration, acceptance.
- `test-pytest-serializer.yaml` — **RocketSerializer**. Paths: `packages/rocketserializer/**`.
  Java 21 + jar reachability check. Matrix py3.10 / 3.12. Runs `tests/unit` then
  `tests/acceptance`.
- `test-icaro.yaml` — **icaro · API · web**. Paths: `packages/icaro/**`, `apps/api/**`,
  `apps/web/**`. Java 21, `uv sync --all-packages --all-groups`, then icaro and api
  unit suites with `-m "not integration"`. Second job runs **Firestore emulator
  integration** tests: `uv sync --package icaro-api --all-groups --extra gcp`, gcloud SDK,
  `cloud-firestore-emulator`, scoped to `tests/test_firestore_emulator.py`.
- There is **no PR-validation workflow** and **no shellcheck job** in this repo.
- All three trigger on PR and push to `main`.

### PR / Issue workflow
- Issue-first: open an issue from a template → maintainer adds `status:approved` → only
  then open a PR linking it with `Closes #N`.
- Conventional Commits, scoped by area when it helps.
- Default branch `main`. Remote `git@github.com:Multitec-UA/icaroRS.git`.
- Enforcement is convention (documented in `CONTRIBUTING.md`), not automation.

### Agent-context file convention
- `AGENTS.md` is the single source of truth at every level.
- Each directory with an `AGENTS.md` has a sibling `CLAUDE.md` containing exactly one
  line: `@AGENTS.md` (Claude Code import syntax, 11 bytes). Symlinks are deliberately
  NOT used — they break on Windows checkouts without `core.symlinks`.
- When adding a new `AGENTS.md` anywhere, add its `CLAUDE.md` stub in the same commit.
- **Exception:** `AGENTS.md` files *inside* `.agents/skills/<name>/` are skill payloads
  shipped by autoskills (e.g. `apps/web/.agents/skills/react-best-practices/AGENTS.md`),
  not project context. Do NOT create `CLAUDE.md` stubs beside them.

### Strict TDD Mode
- **Enabled.** No opt-out marker in `AGENTS.md`/`CLAUDE.md`, and pytest is detected in
  every Python package. `test-icaro.yaml` labels its jobs "TDD suite" explicitly.
- `sdd-apply` and `sdd-verify` MUST write a failing test first, observe RED, then GREEN.
- Test command by area — see the Testing block above.
